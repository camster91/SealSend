# Initial content calendar
Start dates are relative to launch of the experiment. Target one useful guide weekly; pause output if user onboarding needs attention. Search phrases below are intent hypotheses, not validated volumes.

| Week | Asset | Search intent | Real value and CTA |
|---|---|---|---|
| 1 | Existing clubs/community pages + RSVP tracking page | club event RSVP, RSVP tracking | Show the real workflow; create one beta event |
| 2 | Club dinner RSVP checklist | how to track RSVPs | Food counts, plus-ones, deadline, changes; link to tracker |
| 3 | Friendly RSVP reminder messages | RSVP reminder wording | Copyable messages with placeholders; host reviews/sends |
| 4 | QR check-in checklist | event check-in from phone | Roles, real-device test, manual fallback, connection; link to check-in |
| 5 | First host case study if permitted | community event RSVP example | Actual headcount, support effort and host quotation; no invented testimonial |
| 6 | Dietary-question examples | RSVP dietary requirements | Short practical question examples; request only necessary information |
| 7 | Guest list versus chat guide | organize event replies | Honest when a chat or spreadsheet is sufficient |
| 8 | Second case study or improve weakest page | host's actual question | Evidence and friction collected from real beta use |

Every page needs a named author/editor, reviewed date, specific intent, unique help, relevant internal links and a working CTA. Refresh outdated claims monthly. Avoid mass city/occasion pages with swapped keywords. Comparison pages and public template previews remain later work; confirm template capabilities before advertising them.
