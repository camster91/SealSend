## Legacy restore policy

The October 8 nullable-column migration recorded zero RSVP rows. Pre-private-edit invited duplicates or public rows without edit hashes are therefore conditional restore/import risks, not established current incidents. No production historical-data migration is part of this release.

Before importing or restoring older data, inventory duplicate `(event_id, guest_id)` groups and unlinked rows with null `edit_token_hash` on the isolated restored database. Preserve a backup and the old rows. Reconcile invited duplicates only under a separately reviewed, idempotent policy selecting the authoritative newest response and matching guest/plus-one status. Do not attach public legacy replies to a browser using an unverified name or email. Either retain history with a clear new-reply policy or establish identity through an explicitly authorized verified-contact flow. Test capacity, summaries, exports and check-in against those older fixtures before reopening restored event links. A current clean fixture does not prove a legacy restore safe.
